## Operating System Compatibility

Project Janus is designed exclusively for the Windows operating system. It supports the following Windows editions:

- **Windows 10** (all supported versions)
- **Windows 11** (all supported versions)
- **Windows Server** editions (2016 and later)

The application leverages Windows-specific APIs for event log access, which are not available on non-Windows platforms. As such, cross-platform execution (e.g., via Linux or macOS with Mono or .NET Core) is not supported.

## Runtime and Framework Requirements

Project Janus requires the **.NET 9 runtime** to execute. This is explicitly stated in the project documentation and confirmed by the build configuration.

The application is built using modern C# features (C# 13) and depends on .NET 9-specific APIs, particularly for asynchronous event log querying and EF Core integration. Attempting to run the application on earlier .NET versions (e.g., .NET 8 or .NET Framework) will result in runtime errors or failure to launch.

The `version.json` file confirms the project version but does not specify runtime details directly. However, the `README.md` and `GEMINI.md` files explicitly list .NET 9 as a prerequisite.

## Administrative Privileges

Project Janus **requires administrative privileges** to access protected Windows event logs. This requirement is enforced at the application level via the `app.manifest` file, which specifies:


```xml
<requestedExecutionLevel level="requireAdministrator" uiAccess="false" />
```


Without administrator rights, the application will fail to read certain system logs, resulting in partial or failed scans. The `EventLogScannerService` uses `System.Diagnostics.Eventing.Reader.EventLogReader` to query logs, which may throw `UnauthorizedAccessException` if insufficient permissions are present.

The application does not implement self-elevation; users must launch it using "Run as administrator" or configure the shortcut accordingly.

## Storage Considerations

### Snapshot Files (.janus)

Project Janus saves scan results as portable `.janus` snapshot files. These are SQLite database files with a custom extension, created using Entity Framework Core and the `EventSnapshotDbContext`.

Key properties:
- File extension: `.janus`
- Format: SQLite database
- Location: User-specified path during save operation
- Default naming: `JanusSnapshot_YYYY-MM-DDTHH-mm-ssZ.janus` (ISO 8601 UTC timestamp)

The `SnapshotService` class handles both saving and loading of snapshots using `DbContext.Database.EnsureCreatedAsync()`, as migrations are not used per project design.

### Temporary and Runtime Databases

No temporary SQLite databases are created during live scans. All event data is held in memory during scanning. Only when a snapshot is saved is a persistent SQLite file written to disk.

However, the application may create temporary files during EF Core operations, depending on SQLite's internal behavior, though these are not user-visible.

### Storage Estimation

Storage requirements depend on the number of events captured. Each `EventLogEntry` contains:
- `Id` (long), `EventId` (int), `ScanEventId` (int)
- `LogName`, `Level`, `Source`, `Message`, `MachineName` (strings)
- `TimeCreated` (DateTime), `ScanSessionId` (Guid)

The `Message` field typically consumes the most space. As a rough estimate:
- Small scan (1,000 events): ~5–10 MB
- Medium scan (10,000 events): ~50–100 MB
- Large scan (100,000+ events): ~500 MB+

Ensure sufficient disk space is available, especially for systems with verbose logging.

## Hardware Recommendations

While Project Janus has no strict hardware requirements, performance scales with system resources, particularly for large-scale event log scans.

### Recommended Specifications

| Component | Minimum | Recommended |
|---------|---------|-------------|
| **CPU** | Dual-core 2.0 GHz | Quad-core 2.5 GHz or higher |
| **RAM** | 4 GB | 8 GB or more |
| **Storage** | HDD | SSD for faster snapshot load/save |
| **Display** | 1280x720 | 1920x1080 or higher |

### Performance Factors

- **Log Volume**: Systems with many event logs (e.g., servers) will take longer to scan.
- **Time Window**: Larger time windows (e.g., ±60 minutes) increase scan duration and memory usage.
- **Parallel Scanning**: The application scans logs in parallel using `Task.Run`, benefiting from multi-core CPUs.
- **Memory Usage**: All scanned events are stored in RAM during the scan. For very large scans, ensure sufficient free memory to avoid performance degradation.

The `EventLogScannerService` uses throttled progress reporting (default: 250ms or 250 events) to balance UI responsiveness and performance.

## Application Scope and Limitations

### Desktop-Only Application

Project Janus is a **desktop-only application** with no support for remote log collection. It can only scan event logs on the local machine where it is running.

The `EventLogScannerService` uses `EventLogSession.GlobalSession`, which connects to the local event log service. There is no functionality to connect to remote machines or network-based event logs.

### No Remote Collection

Despite the portability of `.janus` snapshot files, the application itself cannot:
- Connect to remote Windows machines
- Query event logs over the network
- Perform distributed or centralized log analysis

Users must run Project Janus directly on the target system to perform a live scan. Snapshots can then be transferred and analyzed offline on other machines.

This design choice simplifies security and deployment but limits use in enterprise environments requiring centralized monitoring.

## Troubleshooting Common Setup Issues

### Missing .NET 9 Runtime

**Symptom**: Application fails to start; error message indicates missing .NET runtime.

**Solution**: Install the .NET 9 SDK or runtime from the official Microsoft website:

```
https://dotnet.microsoft.com/en-us/download/dotnet/9.0
```


Ensure the correct architecture (x64) matches your system.

### Permission Errors (UnauthorizedAccessException)

**Symptom**: Scan fails with "Access is denied" or similar message; some logs show "Failed" status.

**Cause**: Insufficient privileges to read protected event logs.

**Solution**: Run Project Janus as an administrator:
1. Right-click the application or shortcut
2. Select "Run as administrator"
3. Confirm the UAC prompt

Alternatively, modify the shortcut properties to always run as administrator.

### Schema Mismatch or Corrupted Snapshots

**Symptom**: Cannot open a `.janus` file; error message: "Failed to load snapshot."

**Cause**: The snapshot was created with a different version of Project Janus, leading to a database schema mismatch.

**Solution**: The application uses `EnsureCreatedAsync()` and catches `SqliteException` to detect schema issues. Currently, no automatic migration is supported. Options:
- Use the same version of Project Janus that created the snapshot
- Re-scan the logs on the original machine
- Contact the development team for potential conversion tools

### Application Crashes

**Symptom**: Sudden closure with no error dialog.

**Diagnosis**: Check for `janus-crash.log` in the application directory. The `App.xaml.cs` file implements global exception logging.

**Solution**: Review the log file for stack traces and report issues to the development team.
