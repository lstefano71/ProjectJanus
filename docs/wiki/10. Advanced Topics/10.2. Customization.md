## Modifying Default Scan Settings via UserUiSettingsService

The `UserUiSettingsService` class is responsible for managing and persisting user interface settings across application sessions. It uses a JSON file named `UserUiSettings.json` located in the application's base directory to store settings. This service enables customization of scan parameters such as the time window (minutes before and after the selected timestamp) and maintains UI state like window dimensions and splitter positions.

The `UiSettings` class within `UserUiSettingsService` defines the following configurable properties:
- **MinutesBefore**: Default value is 5 minutes.
- **MinutesAfter**: Default value is 5 minutes.
- **MainWindowWidth**: Default value is 900 pixels.
- **MainWindowHeight**: Default value is 400 pixels.
- **ResultsSplitterPosition**: Relative position (0–1) of the results panel splitter.
- **DetailsSplitterPosition**: Relative position (0–1) of the details panel splitter.
- **RecentSnapshots**: A list of recently opened snapshot file paths, limited to the 10 most recent entries.

Settings are loaded asynchronously at startup in view models such as `LiveScanViewModel` and `ResultsViewModel`. For example, in `LiveScanViewModel`, the `LoadUiSettingsAsync` method retrieves the stored values and applies them to the `MinutesBefore` and `MinutesAfter` properties. Any changes to these values trigger `SaveUiSettingsAsync`, which persists the updated settings back to the JSON file.


```csharp
private async Task LoadUiSettingsAsync() {
    UserUiSettingsService.UiSettings settings = await UserUiSettingsService.LoadAsync();
    MinutesBefore = settings.MinutesBefore;
    MinutesAfter = settings.MinutesAfter;
}

private async Task SaveUiSettingsAsync() {
    UserUiSettingsService.UiSettings settings = await UserUiSettingsService.LoadAsync();
    settings.MinutesBefore = MinutesBefore;
    settings.MinutesAfter = MinutesAfter;
    await UserUiSettingsService.SaveAsync(settings);
}
```


A semaphore ensures thread-safe file access during read and write operations, preventing race conditions in multi-threaded scenarios.

## UI Customization Options

### Theme Adjustments via XAML Resources

UI appearance can be customized through XAML resources defined in `App.xaml`. These resources include brushes for background, border, and foreground colors, which are applied globally across controls. For example:


```xml
<SolidColorBrush x:Key="ControlBackgroundBrush" Color="White"/>
<SolidColorBrush x:Key="ControlBorderBrush" Color="#CCC"/>
<SolidColorBrush x:Key="ControlForegroundBrush" Color="Black"/>
```


These brushes are referenced using `DynamicResource` in control templates, allowing dynamic theme switching at runtime. Modifying these values changes the look and feel of the entire application without requiring code changes.

### Control Templating for Custom Visuals

Custom control templates, such as the `JanusLogoIcon`, allow for reusable vector graphics. These templates can be modified to reflect branding or aesthetic preferences. The logo is defined using `Path` and `Ellipse` elements within a `Canvas`, enabling precise control over visual details.

### Dynamic UI Element Injection Using Attached Behaviors

The `DataGridGroupStyleBehaviour` class enables dynamic grouping in the `DataGrid` by conditionally applying a `GroupStyle`. This behavior is implemented as an attached property using the Microsoft.Xaml.Behaviors library.


```csharp
public class DataGridGroupStyleBehavior : Behavior<DataGrid> {
    public static readonly DependencyProperty GroupStyleProperty = DependencyProperty.Register(
        nameof(GroupStyle), typeof(GroupStyle), typeof(DataGridGroupStyleBehavior), new PropertyMetadata(null));

    public static readonly DependencyProperty IsEnabledProperty = DependencyProperty.Register(
        nameof(IsEnabled), typeof(bool), typeof(DataGridGroupStyleBehavior), new PropertyMetadata(false, OnIsEnabledChanged));

    private static void OnIsEnabledChanged(DependencyObject d, DependencyPropertyChangedEventArgs e) {
        var behavior = (DataGridGroupStyleBehavior)d;
        behavior.ApplyGroupStyle((bool)e.NewValue);
    }

    private void ApplyGroupStyle(bool isEnabled) {
        if (AssociatedObject == null) return;
        AssociatedObject.GroupStyle.Clear();
        if (isEnabled && GroupStyle != null) {
            AssociatedObject.GroupStyle.Add(GroupStyle);
        }
    }
}
```


In `ResultsView.xaml`, this behavior is attached to the `DataGrid` and bound to a view model property (`IsAnyGroupingEnabled`), allowing users to toggle grouping dynamically:


```xml
<i:Interaction.Behaviors>
  <local:DataGridGroupStyleBehavior 
        GroupStyle="{StaticResource MyEventGroupStyle}"
        IsEnabled="{Binding IsAnyGroupingEnabled}" />
</i:Interaction.Behaviors>
```


This approach supports MVVM by keeping UI logic in the view and state management in the view model.

## Environment-Aware Path Resolution with EnvVarContractor

The `EnvVarContractor` class enables portable deployments by resolving environment variables in file paths. It scans the current environment variables and replaces the longest matching prefix with the corresponding `%VARIABLE%` syntax.


```csharp
public static string ContractPath(string path) {
    string? bestVar = null;
    string? bestValue = null;
    int bestLen = 0;
    foreach (DictionaryEntry env in Environment.GetEnvironmentVariables()) {
        string var = env.Key.ToString()!;
        string value = env.Value.ToString()!;
        string normValue = Path.GetFullPath(value).TrimEnd(Path.DirectorySeparatorChar) + Path.DirectorySeparatorChar;
        string normPath = Path.GetFullPath(path);
        if (normPath.StartsWith(normValue, StringComparison.OrdinalIgnoreCase) && normValue.Length > bestLen) {
            bestVar = var;
            bestValue = normValue;
            bestLen = normValue.Length;
        }
    }
    if (bestVar != null && bestValue != null) {
        string contracted = "%" + bestVar + "%" + path[(bestValue.Length - 1)..];
        return contracted;
    }
    return path;
}
```


This is particularly useful for snapshot file paths, allowing configurations to be shared across machines with different drive letters or user directories. For example, a path like `C:\Users\Alice\Documents\janus\snapshots\scan.jss` can be contracted to `%USERPROFILE%\Documents\janus\snapshots\scan.jss`.

## Examples of UI Customization

### Modifying Placeholder Text

The `TextBoxWithPlaceholder` control supports customizable placeholder text via the `Placeholder` dependency property:


```csharp
public string Placeholder {
    get => (string)GetValue(PlaceholderProperty);
    set => SetValue(PlaceholderProperty, value);
}
```


In XAML, it is used as:

```xml
<controls:TextBoxWithPlaceholder
    Text="{Binding SearchText}"
    Placeholder="Filter event messages..."/>
```


### Customizing Grid Layouts

The `BooleanToGridLengthConverter` allows dynamic column resizing based on boolean states. For example, it can expand or collapse a metadata panel:


```csharp
public class BooleanToGridLengthConverter : IValueConverter {
    public GridLength ExpandedWidth { get; set; } = new GridLength(220);
    public GridLength CollapsedWidth { get; set; } = new GridLength(0);

    public object Convert(object value, Type targetType, object parameter, CultureInfo culture) {
        return (value is bool b && b) ? ExpandedWidth : CollapsedWidth;
    }
}
```


Used in XAML:

```xml
<ColumnDefinition Width="{Binding IsExpanded, ElementName=MetadataExpander, Converter={StaticResource BoolToGridLength}}"/>
```


### Data Binding Converters for Tailored Experiences

Converters like `StringNotEmptyToVisibleConverter` control element visibility based on data:

```csharp
public object Convert(object value, Type targetType, object parameter, CultureInfo culture) => 
    value is string s && !string.IsNullOrWhiteSpace(s) ? Visibility.Visible : Visibility.Collapsed;
```


This is used to show a "Snapshot Path" field only when a file path is available.

## Configuration Management Across Profiles and Deployments

The `UserUiSettingsService` supports multiple deployment scenarios by storing settings in a local JSON file. This enables:
- **Portable deployments**: Settings travel with the application.
- **User-specific profiles**: Each user gets their own `UserUiSettings.json`.
- **Easy backup and migration**: The JSON file can be copied between machines.

Recent snapshots are managed via `AddRecentSnapshotAsync`, which maintains an MRU list of up to 10 entries. This list is persisted across sessions and shared across views (`WelcomeViewModel`, `ResultsViewModel`).

To safely override default styles without breaking MVVM bindings:
- Use `DynamicResource` instead of `StaticResource` for theme brushes.
- Avoid modifying `DataContext` or command bindings in control templates.
- Prefer attached behaviors over code-behind for dynamic UI logic.

This ensures that visual changes do not interfere with data flow or command execution.
